# AI features (Phase 2 and 3)

AI helps with words, search and suggestions. It never decides a price, a stock number, a balance or an order
status; those always come from the database.

## How a call works

```
Feature code (API)                     apps/api/app/modules/assist/gateway.py        apps/ai-service
──────────────────                     ─────────────────────────────────────        ───────────────
build facts from the DB  ──ask()──▶    1. feature switch on? (ai_features)   ──▶   llm.complete()
                                       2. monthly budget left?                        Claude (Anthropic SDK)
                                       3. POST with short timeout                     returns text + usage
use AI text if it passes  ◀─────────   4. log tokens + cost in ai_usage      ◀──    {"source": "ai" | "fallback"}
the check, else fallback               5. alert at 80% and 100% of budget
```

`gateway.ask` returns `None` on any problem (switch off, budget used, timeout, error, no API key). Every caller
then uses its own non-AI answer. This is SRS test **T32**: all features keep working with the AI service off.

The AI service (`apps/ai-service/app/llm.py`) uses the official `anthropic` Python SDK, model from
`AI_MODEL_TEXT` (default `claude-opus-5-5`), effort `low` for short tasks and `medium` for descriptions and the
buying summary. Without `ANTHROPIC_API_KEY` it answers `source: "fallback"` straight away.

## Features

| SRS | Feature | Endpoint | Uses Claude? | Fallback / guard |
|---|---|---|---|---|
| AI-0 | WhatsApp wording | worker → `/ai/message/compose` | yes | Numbers checked against facts (T08) → approved template |
| AI-1 | Recommendations (similar, also bought, complete the look, picked for you) | `GET /ai/recommendations` | no — own sales data and tokens | Bestsellers |
| AI-2 | Support chatbot | `POST /ai/chat` | yes, with FAQ + product facts only | FAQ answer; order status from DB only for its owner; no discounts or khata (T33) |
| AI-3 | Smart search (Hindi / Hinglish) | `GET /ai/search` | only for long queries | Rule parser (colour, fabric, price words); empty results logged as customer requests |
| AI-4 | Size help | `POST /ai/size`, `GET /ai/size-chart` | no | Size chart from Settings + past "too small / too big" returns |
| AI-5 | Description writer | `POST /ai/describe` | yes, with photo | Simple description from product facts; staff edit before saving |
| AI-6 | Poster maker | `POST /ai/poster`, `POST /ai/poster/copy` | wording suggestions only | SVG template prints the exact text staff typed |
| AI-7 | Visual search | `POST /ai/visual-search` | no | Colour / pattern signature of product photos |
| AI-8 | Demand and trend forecast | `GET /ai/forecast`, `GET /ai/trends` | no | Smoothing + weekday pattern + last year's season; confidence label |
| AI-9 | What to buy | `GET /ai/what-to-buy` | summary only | Reorder list is computed; every number in the AI summary must appear in the facts (`buying.numbers_ok`), else no summary |
| — | Usage | `GET /ai/usage` | — | Spend this month vs budget, per feature |
| — | Rebuild index | `POST /ai/index/refresh` | — | Also runs nightly and on product change |
| — | Customer requests | `GET/POST/PATCH /ai/missing-requests` | — | Staff review and mark done |

Code: `apps/api/app/modules/assist/` — `catalog_ai.py` (recommend, search, size, visual), `buying.py`
(forecast, trends, what to buy), `chat.py`, `copywriter.py` (describe, posters), `text.py` (Hinglish words),
`gateway.py`. AI service: `apps/ai-service/app/features.py`, `messages/compose.py`.

## Controls (Settings → AI)

| Setting | Default | Meaning |
|---|---|---|
| `ai_features` | all on | Switch per feature: message, recommend, chat, search, size, describe, poster, visual, forecast, buying |
| `ai_monthly_budget_paise` | 500000 (₹5,000) | Shared limit; at 100% AI calls stop until next month |
| `ai_cost_paise_per_mtok` | input 34000, output 170000 | **Estimate** used to count spend. Check against the real Anthropic bill |
| `chat_retention_days` | 90 | Chat history older than this is deleted |
| `size_charts`, `complete_the_look`, `faq` | sample values | Replace with the shop's own |

## Privacy

- The AI service gets only what a feature needs: product facts and FAQ text. For WhatsApp wording it gets
  only the purpose, language and placeholder names (`{first_name}`, `{amount}`); the API fills in the real
  values after the AI answers. No phone numbers, khata balances or salary data are sent.
- Chat shows a notice that the customer is talking to an AI assistant.
- Order status in chat is shown only to the logged-in owner or to someone who gives the order's mobile number;
  the reply is the same whether the order exists or not.

## Limits to know

- Visual search compares colours and patterns; it is not a deep image model.
- Posters are templates; no image is generated by AI.
- Forecasts need sales history; new items get a "low" confidence label.

## Tests

`apps/api/tests/test_ai_phase2_3.py` runs every feature with the AI service off (the gateway is patched to
return `None`), plus the budget cap and the number check.
